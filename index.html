Process Isolation: TicketPrinter

Child Process Forking (fork & waitpid)

The C++ backend isolates thermal printing into a separate child process via fork(). This keeps the parent booking loop non-blocking while waitpid() reaps the child cleanly to eliminate zombie processes.

C++ Implementation snippet:
pid_t pid = fork();
if (pid == 0) {
  // Child: render ticket & flush
  _exit(0);
} else {
  waitpid(pid, &status, 0); // Reaping
}

The database follows 3rd Normal Form (3NF) relational design across 9 core entities with strict foreign key constraints and cascading deletes:
1. customers
  • cust_id INT (PK, AUTO_INC)
  • name VARCHAR(100)
  • phone_no BIGINT (UNIQUE)
2. movies
  • movie_id INT (PK, AUTO_INC)
  • title VARCHAR(255)
  • language VARCHAR(50)
  • duration_mins INT
3. screens
  • screen_id INT (PK)
  • screen_number INT
  • silver_count INT
  • gold_count INT
  • platinum_count INT
4. seats
  • seat_id INT (PK)
  • screen_id INT (FK → screens)
  • seat_number INT
  • seat_type VARCHAR(20)
5. shows
  • show_id INT (PK)
  • movie_id INT (FK → movies)
  • screen_id INT (FK → screens)
  • start_time INT
  • end_time INT
6. show_seats
  • show_seat_id INT (PK)
  • show_id INT (FK → shows)
  • seat_id INT (FK → seats)
  • seat_number INT
  • status VARCHAR(20)
7. bookings
  • booking_id INT (PK)
  • cust_id INT (FK → customers)
  • show_id INT (FK → shows)
  • total_amount INT
  • booking_status TINYINT(1)
8. booking_seats
  • id INT (PK)
  • booking_id INT (FK → bookings)
  • show_seat_id INT (FK → show_seats)
9. payments
  • payment_id INT (PK)
  • booking_id INT (FK → bookings)
  • amount INT
  • payment_method VARCHAR(20)
